## Decisions this week

- **[ADR 0014](../adr/0014-asset-upload.md), accepted 2026-11-18:** the server may depend on `integrations/asset-pipeline` and nothing else under `integrations/`. Upload is `POST /campaigns/{id}/assets`, GM only, authorised by the socket's token. Files are stored on disk by content hash and served from `/assets/<sha256>.<ext>`. `SetLevelBackgroundIntent` carries only the asset id. `tools/check-deps.sh` enforces this (rules 7 and 8), and ADR 0013's M1 row now names the upload work.
- Not an ADR, but fixed in the contracts ([#71](https://github.com/Henry-theBinaryBuddies/TomeAndTile/pull/71)):
  - A multi-attack ability takes one target per attack step, in order. Extra targets are ignored, and a step with no target is not rolled.
  - The rejection codes and warning codes for `UseAbilityIntent` are listed in the proto comments.
- Agreed on issue 64 with @Danny-Defeato: the renderer's picking interface (`setPicking`, `onPick`, `setHighlights`). The renderer holds no targeting rules.

## What did not get done, plainly

- **No real video call yet.** The LiveKit Cloud project (issue 5) does not exist in the repository's record, so the M1 video item is not met. The join token and the client module are tested only against fakes.
- **Contributor M2 work is open, not merged.** Seven contributor pull requests are open, and six of them still need changes or answers to comments.
- **Mock and real servers differ on one case.** When one `UseAbilityIntent` has several faults at once, the real server reports `unknown_target` before `no_targets` or `not_implemented`, and the mock reports them in the other order. A single fault gets the same code from both.
- **Not tested on a real phone.** Target picking on the map was checked only with simulated touch events. The WebGL2 fallback has still not run with dragging or picking.
- **Not ready to deploy.** The server still has no sign-in other than the development stand-in, no rate limit and no cap on its event log.
- **SRD values unchecked.** The SRD character values have still not been checked line by line against the SRD.
