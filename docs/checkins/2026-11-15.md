## Decisions this week

- All 13 ADRs were accepted on 2026-11-12.
- ADR 0006 amended by [#19](https://github.com/Henry-theBinaryBuddies/TomeAndTile/pull/19) (2026-11-13): dice animation uses the dice-box library. One open point is recorded in the ADR: the animation must land on the server's numbers; if the library cannot be made to, the roll card's numbers stay authoritative and the animation is decoration.
- Not an ADR, but decided with the project owner: no automated death saves; player rolls always public with only GM rolls hideable; the server rolls initiative with a GM override; the GM can hand a token to a player.
- The M0 UI shell ([#25](https://github.com/Henry-theBinaryBuddies/TomeAndTile/pull/25)) uses SvelteKit and no docking library, with layout state in one store, which is what issue 10 and ADR 0001 allow.

## What did not get done, plainly

- The LiveKit Cloud project does not exist, so no token has been tried against real LiveKit. The join-token code is tested only against its own signing code, and one claim (`name`) is not confirmed by LiveKit's documentation.
- The renderer has never drawn a map or token image (the mock fixture has none), and its WebGL2 fallback has never run.
- The SRD character fixtures were written from memory and have not been checked line by line against the SRD document.
- The server has no sign-in other than a development stand-in, no rate limit and no cap on its event log. It must not be deployed as it is.
- No browser client connects to the server yet, so nothing in M1 can be shown in two browsers.
