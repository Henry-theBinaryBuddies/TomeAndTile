## 2026-11-20 — Map follow-up: no silent drop of waiting frames

**Did:** Follow-up to [#32](https://github.com/Henry-theBinaryBuddies/TomeAndTile/issues/32). The map controller kept the newest 200 frames while the renderer was starting and dropped older ones. If the first Snapshot was among the dropped frames, the later updates would have been drawn onto an empty map with no warning. The controller still decodes nothing, so it cannot tell which frame is a Snapshot; stopping with a message was the honest option. One test replaced by two (17 map tests pass; 306 in total on top of #76); check passes. I also checked the other point I had in mind, that the map's refusal notice might show refusals of chat or dice: it does not, because the renderer only reports refusals of its own token moves (`model.rs`), so nothing changes there.
**Directed Claude to:** Keep the change to the controller and its tests, not decode messages in `web/`, and prefer a visible stop over silently losing data.
**Learned:** My earlier note that the renderer reports every refusal was wrong; the README and `model.rs` both say only its own moves, so I read the source before changing anything.
